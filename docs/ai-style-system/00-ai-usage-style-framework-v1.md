# AI 使用风格框架 v1（Beta）

> 英文名：AI Usage Style Framework（AUSF）
> 版本：1.0.0-beta
> 定位：教育与自我发展工具，不是心理诊断或能力考试

## 1. 测量对象

AI 使用风格指：一个人在探索、应用、理解和委托 AI 完成任务时，相对稳定但会随情境与经验变化的行为偏好。

它回答“我通常喜欢怎样与 AI 工作”，不回答：

- 我聪不聪明；
- 我的 AI 水平高不高；
- 我是否适合某个职业；
- 我是否应该进入高级学习群；
- 我是否应当把更多事情交给 AI。

能力测评决定课程准备度和社群层级；使用风格只改变案例、练习形式、同伴匹配和报告表达。两套结果不得互相推断。

## 2. 四条连续轴

| 轴 | 第一端 | 第二端 | 测量的偏好 | 绝不能解释成 |
|---|---|---|---|---|
| E–S | Explore 探索 | Systematize 系统化 | 尝试新可能，或沉淀稳定方法 | 创新 vs 保守 |
| C–O | Create 创造 | Optimize 优化 | 创造新成果，或改善既有工作 | 有创意 vs 没创意 |
| R–A | Reason 理解 | Act 行动 | 先理解原因，或先行动迭代 | 高智商 vs 低智商 |
| P–D | Partner 共创 | Delegate 委托 | 多轮参与协作，或设定边界后委托 | 初级 vs 高级 |

每条轴在数据库中保存第一端 0–100 分，第二端等于 `100 - 第一端分数`。四字母代码只是传播层的摘要，不替代连续分数。

例如：

```text
探索 Explore       73 ━━━━━━━━━━━━━━━○━━━━ 27 系统化 Systematize
创造 Create        66 ━━━━━━━━━━━━━○━━━━━━ 34 优化 Optimize
理解 Reason        58 ━━━━━━━━━━━○━━━━━━━━ 42 行动 Act
共创 Partner       71 ━━━━━━━━━━━━━━○━━━━━ 29 委托 Delegate
```

公开结果可写作 `ECRP · AI好奇发明家`，详细报告必须同时展示四条连续轴。

## 3. 平衡与偏好清晰度

Beta 阶段暂用离 50 的距离表示回答倾向的清晰程度：

| 第一端分数 | 内部分类 | 用户文案 |
|---|---|---|
| 45–55 | balanced | 两侧较平衡，可能取决于任务情境 |
| 38–44 / 56–62 | slight | 略偏向一侧 |
| 28–37 / 63–72 | moderate | 有较明显偏好 |
| 0–27 / 73–100 | clear | 本次回答呈现清晰偏好 |

这些不是统计置信区间。正式阈值需在获得重测信度与测量误差后校准。即使 50/50，也会为了生成分享代码而采用第一端字母，但报告必须标记为“平衡”，不能把 49 与 51 描述成完全不同的人。

## 4. 十六种传播画像

| 代码 | 中文名 | 典型工作方式 | 常见盲点假设 |
|---|---|---|---|
| ECRP | AI好奇发明家 | 探索、创造、理解、共创 | 实验很多，沉淀较少 |
| ECRD | AI实验导演 | 理解新能力后扩大委托 | 边界未成熟时过早委托 |
| ECAP | AI创意冲刺者 | 快速试验并做出新成果 | 记录与核验不足 |
| ECAD | AI原型启动者 | 快速探索和推动原型 | 验证不足就扩大范围 |
| EORP | AI流程侦察员 | 寻找效率新方法并保持参与 | 频繁切换工具 |
| EORD | AI自动化开拓者 | 探索并设计自动化 | 为简单问题过度设计 |
| EOAP | AI效率实验家 | 快速寻找即时提效方法 | 只做局部优化 |
| EOAD | AI运营探索者 | 尝试工具并委托重复工作 | 工具和权限堆积 |
| SCRP | AI深度匠人 | 深入掌握并持续共创 | 采用新路径较慢 |
| SCRD | AI产品架构师 | 先理解设计，再稳定委托 | 分析阶段过长 |
| SCAP | AI实用创作者 | 用熟悉方法快速创造 | 错过新的可能 |
| SCAD | AI生产构建者 | 把创造方法变成生产系统 | 流程逐渐僵化 |
| SORP | AI流程分析师 | 理解流程并共同改善 | 过度分析、延迟尝试 |
| SORD | AI系统规划师 | 设计稳定可解释的优化系统 | 探索速度较慢 |
| SOAP | AI稳健优化师 | 务实协作、持续改善 | 只做渐进改良 |
| SOAD | AI运营编排者 | 把成熟方法变成委托系统 | 自动化稳定后减少抽查 |

所有名称和盲点都是待验证的 UX 假设，不能作为“科学人格类型”宣传。正式发布前应进行名称理解度与分享意愿测试。

## 5. 对教学和社区的作用

风格只调节学习体验：

- E：提供多工具小实验；S：提供可沉淀模板；
- C：优先使用内容、产品和原型案例；O：优先使用办公与流程案例；
- R：解释优先；A：挑战优先；
- P：多轮共创练习；D：边界、权限、监控和 Agent 委托练习。

能力等级仍独立决定 Starter、Application、Practice 等学习群。风格可以作为群内兴趣标签，不得形成高低排序。

## 6. 报告声明

页面应明确展示：

> 本测评用于教育和自我发展，不是心理诊断、智力测试、职业筛选或专业认证。结果描述的是你当前与 AI 工作时的偏好，不表示能力、价值或未来成就；偏好可能随任务和经验变化。
