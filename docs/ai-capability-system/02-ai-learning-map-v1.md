# 个人 AI 学习地图 v1.0

> 版本：1.0.0  
> 日期：2026-08-09  
> 依据：[个人 AI 能力框架 v1.0](./01-ai-capability-framework-v1.md)  
> 目标：把“测出等级”变成“知道下一步学什么、做什么、如何证明学会”

## 一、这张地图如何使用

学习地图不是强迫所有人从第一节重学。使用流程是：

1. 快测识别大致起点、风险和数字基础缺口。
2. 全测确认六维能力、晋级门槛和可跳过模块。
3. 先补**安全门槛与阻塞性前置能力**，再走目标场景路线。
4. 每个阶段以真实作品结业，不以“看完视频”结业。
5. 30–90 天复测，用平行任务比较迁移和成长。

## 二、总路线

```text
数字生存补给（按需）
        ↓
L0 认识 AI：纠正心智模型，安全完成第一次尝试
        ↓
L1 借助 AI：在模板和检查表下完成低风险单步任务
        ↓
L2 独立应用：端到端完成一个常见真实任务
        ↓
L3 深度协作：管理复杂任务、证据、状态和复用资产
        ↓
L4 构建系统：设计可靠 Workflow/Agent 并持续评测
        ↓
L5 推动变革：形成组织采用、治理和价值闭环
```

旁路专长贯穿 L1–L4：

- 办公与运营
- 学习与研究
- 内容与创意
- 产品与创业
- 编程与 Codex

专长路线改变练习场景，不改变通用等级的安全与核验门槛。

## 四、六个阶段的详细路线

## L0 → L1：从围观到安全起步

### 学习目标

- 能说清模型、AI 产品、搜索、Workflow 和 Agent 的基本区别。
- 知道生成式模型可能输出错误、旧信息和虚构来源。
- 能判断明显敏感数据不应直接上传。
- 能按一个简单任务契约完成低风险任务。

### 推荐顺序

1. 按快测结果选 BRG-00/01/02。
2. CORE-01 AI 世界地图。
3. CORE-02 安全起步。
4. CORE-03 第一个任务契约。

### 必做练习

**同一任务五张卡**：给出“总结一份会议记录”，让学员区分以下方案：

1. 直接向模型提问；
2. 聊天产品上传文件；
3. 搜索/检索外部材料；
4. 固定工作流自动整理；
5. Agent 自主调用日历和任务系统。

学员必须说明每种方案的输入、权限、风险和是否必要。

### 阶段作品

《我的第一个 AI 辅助成果包》：原始需求、任务契约、AI 草稿、人工修订、事实检查和最终交付。

### 通关条件

- 概念边界题通过；
- 不发生明显隐私/密钥错误；
- 能指出输出中至少一个需要核验的主张；
- 低风险成果达到最低验收标准。

### 常见失败

- 只背产品名，不理解构件；
- 把“角色 + 任务 + 格式”当万能提示词；
- 认为表达流畅就等于事实正确；
- 因数字操作卡顿被误判为“学不会 AI”。

## L1 → L2：从模板使用到独立交付

### 学习目标

- 能判断任务适不适合 AI，独立定义结果和验收标准。
- 能拆解任务、选择工具、提供材料并多轮纠偏。
- 能打开原始来源核验事实，不把模型引用当证据。
- 能完成一个常见、低到中等风险的端到端真实任务。

### 推荐顺序

1. CORE-04 不把 AI 当搜索。
2. CORE-05 第一次真实交付。
3. CORE-06 拆解、委派与多轮纠偏。
4. CORE-07 工具选型与多模态工作区。
5. CORE-08 质量工程。
6. CORE-09 数据、版权、披露与账户边界。
7. 选择一条场景专长的 01 模块。

### 必做练习

- **先标准、后生成**：在看 AI 答案前写验收表，再盲评两份不同模型输出。
- **主张—证据表**：从 AI 草稿中抽取 5 个关键主张，逐一找到原始来源、发布日期和适用条件。
- **陌生工具迁移**：换一个未学过的聊天产品，完成同类任务并解释差异。

### 阶段作品

任选真实场景完成一个可交付成果，例如：

- 一份带来源的行业简报；
- 一套会议纪要—任务—跟进包；
- 一篇经过事实与版权检查的内容作品；
- 一个个人学习计划及每周复盘表；
- 一个可运行的小型无代码/代码原型。

### 通关条件

- 不是照抄教师提示词；
- 关键事实和来源可追溯；
- 最终结果满足预先写定的标准；
- 能解释 AI 做了什么、人做了什么、仍有哪些不确定性。

### 常见失败

- 工具越多越有能力；
- 输出越长越专业；
- “我让 AI 不要编”被当成核验；
- 只会当前教程的界面步骤，无法迁移。

## L2 → L3：从独立完成到深度协作

### 学习目标

- 能处理多阶段、多材料、冲突要求和不完整信息。
- 会管理长任务的状态、上下文、交接和版本。
- 将 AI 用于备选方案、反驳、评审和综合，而不只代写。
- 把一次成功沉淀为模板、知识资产或 SOP，并测量效果。

### 推荐顺序

1. CORE-10 个人 SOP 与复用模板。
2. CORE-11 复杂人机协作。
3. CORE-12 研究、综合与证据链。
4. CORE-13 知识资产。
5. CORE-14 效果测量。
6. CORE-15 团队协作与人工审批。
7. 场景专长 02 模块。

### 必做练习

- **长任务接力**：在三个会话/工具之间通过状态文件完成任务，任何一步不能依赖“AI 应该记得”。
- **红队与反方**：先生成方案，再由独立模型/同伴按验收表找错，最后由人裁决。
- **复用测试**：让另一位学员只依赖你的模板/SOP 完成同类任务，记录失败点。

### 阶段作品

《AI 协作项目档案》包含：

- 问题定义与利益相关者；
- 任务拆解与人机分工；
- 来源、版本和决策日志；
- 中间失败与纠偏；
- 最终成果与验收；
- 可复用资产；
- AI 前后时间、质量和风险对比。

### 通关条件

- V 维度至少达到 L2；
- 能在未知变化下重新规划，而非只重复提示；
- 有证据说明成果可用且复用资产确实帮助第二次任务；
- 不把 AI 替代领域判断。

### 常见失败

- 长对话中继续堆指令，不做状态整理；
- 让同一个模型“既写又自证”；
- 把生成速度当成业务价值；
- 过度依赖 AI，导致自己无法解释最终结果。

## L3 → L4：从个人工作流到可靠系统

### 学习目标

- 从真实流程发现值得系统化的问题，而非先选技术。
- 正确选择单次调用、固定 Workflow 或 Agent。
- 设计状态、异常、重试、权限、人工审批和失败恢复。
- 建立离线/在线评测、日志、成本和质量监控。

### 推荐顺序

1. SYS-01 流程发现与价值判断。
2. SYS-02 Workflow 架构。
3. SYS-03 API、数据、连接器、权限与成本。
4. SYS-04 Agent 架构与最小自主性。
5. SYS-05 Evals 与可观测性。
6. SYS-06 Guardrails、安全攻击与失败恢复。
7. SYS-07 可靠 AI 系统毕业项目。

### 架构决策阶梯

对每个用例依次问：

1. 不用 AI 能否更稳定、便宜？
2. 一次人工触发的模型调用是否足够？
3. 固定 Workflow 能否覆盖主要分支？
4. 哪一部分确实需要模型动态选择下一步？
5. Agent 获得什么最小权限？什么情况必须停下并请人处理？

前一层足够时，不因“技术更炫”升级到后一层。[S18][S20]

### 必做练习

- **工作流失效演习**：输入缺失、工具超时、重复回调、错误来源、成本飙升各一次。
- **提示注入演习**：不可信网页/文件试图让 Agent 泄露密钥或执行越权操作。
- **回归评测**：修改提示、模型或工具后，运行固定测试集并比较质量/成本/延迟。

### 阶段作品

一个真实运行的 Workflow 或 Agent，至少包含：

- 业务问题和不自动化理由；
- 架构图与数据流；
- 权限清单和人工审批点；
- 20+ 个代表性评测样本；
- 日志、指标、成本和版本；
- 失败恢复与回滚方案；
- 两周以上试运行记录（认证版要求）。

### 通关条件

- V、S 维度至少 L3；
- 实作通过，不接受只看演示视频；
- 能证明系统比更简单方案更适合；
- 出错可发现、可停止、可追踪、可恢复。

### 常见失败

- 一上来多 Agent；
- 只测试 happy path；
- 把“知识库/RAG”当成不会幻觉的保证；
- 密钥、权限、成本和日志等上线问题留到最后。

## L4 → L5：从系统构建到组织变革

### 学习目标

- 建立用例组合、价值优先级和停止投资标准。
- 形成角色、政策、培训、社区支持和责任矩阵。
- 用采用、质量、风险、成本和业务结果衡量改变。
- 管理供应商、数据、模型变化、审计和事件响应。

### 推荐顺序

1. ORG-01 AI 用例组合与价值优先级。
2. ORG-02 AI 治理、政策与责任矩阵。
3. ORG-03 采用、培训与社区运营。
4. ORG-04 组织级评测、审计与事件响应。
5. ORG-05 AI 变革实验室。

### 必做练习

- **用例投资委员会**：在收益、风险、准备度和不可逆性之间排序，不允许全部立项。
- **事故桌面推演**：模拟隐私泄露、错误自动发布、模型退化或供应商中断。
- **采用诊断**：区分“没有权限/工具”“不会用”“流程不支持”“激励不匹配”四类阻力。

### 阶段作品

《组织 AI 化 90 天方案》：

- 基线与目标；
- 用例组合及负责人；
- 能力分层与培训路线；
- 工具、数据和权限政策；
- 评测、审计和事件响应；
- 社区/冠军网络与支持机制；
- 价值、采用和风险指标；
- 30/60/90 天复盘与停止条件。

### 通关条件

- V、S 维度至少 L4；
- 通过组织级情境答辩；
- 至少有一个真实团队采用案例与结果证据；
- 既能扩大有效用例，也能停止无效或高风险用例。

## 六、个性化选课规则

### 6.1 推荐算法的顺序

```text
安全门槛失败？ → CORE-02 / CORE-08 / CORE-09 / SYS-06
数字基础阻塞？ → BRG-00 / BRG-01 / BRG-02
目标等级前置能力缺失？ → 对应 CORE/SYS 模块
目标场景是什么？ → OFF/RES/CON/PROD/DEV
已有作品证据足够？ → 可跳过模块，直接挑战项目
```

### 6.2 不应推荐的方式

- 仅按总分推荐一整套固定课程；
- 因用户自称“高级”而跳过核验；
- 因用户是程序员而跳过任务/治理；
- 因用户不会代码而阻止进入系统设计；
- 同时推荐十几门课，制造新的工具焦虑。

### 6.3 一次报告只给三步

每次测评只给：

1. **一项必须先补的门槛能力**；
2. **一项最接近真实目标的核心能力**；
3. **一个能证明成长的作品任务**。

其余模块放入“稍后学习”，避免路径过载。

## 七、教学方法

### 7.1 每个模块的最小结构

1. 一个真实失败案例或误解；
2. 一个稳定概念模型；
3. 教师示范并说出判断依据；
4. 学员在相似任务练习；
5. 学员在陌生任务迁移；
6. 按 rubric 同伴/教师反馈；
7. 沉淀模板、作品和复盘。

### 7.2 让 AI 参与教学但不替代学习

- AI 可做即时反馈、反方、模拟客户和个性化练习生成器。
- 学员必须保留一部分“先独立判断”的步骤，避免把认知工作全部外包。
- 重要任务先写目标和判断，再看 AI 建议；最终由学员解释和负责。[S12]

### 7.3 不教“万能提示词”

可以教模板，但模板必须可拆解：目标、材料、约束、样例、标准、迭代。考核时更换场景和工具，验证迁移而非背诵。

## 八、社群学习机制

| 社群 | 每周节奏 | 主要产物 | 助教关注 |
|---|---|---|---|
| L0–L1 起步群 | 1 个概念纠偏 + 1 个小任务 | 第一次成果包 | 数字基础、隐私和挫败感 |
| L2 应用群 | 1 个真实场景挑战 + 作品互评 | 端到端成果 | 来源、验收、迁移 |
| L3 协作群 | 复杂项目冲刺 + 复盘 | 协作项目档案 | 状态、证据、复用与效果 |
| L4–L5 系统群 | 架构诊所 + 事故演练 | 系统/组织案例 | 评测、权限、成本、采用 |

群内身份以四位入群 ID 展示即可。能力等级来自测评版本和证据，不由群昵称、付费状态或活跃度决定。

## 九、90 天样例路径

### 9.1 真正小白

- 第 1–2 周：BRG-00 + CORE-01 + CORE-02。
- 第 3–4 周：CORE-03 + CORE-04，完成第一次成果。
- 第 5–8 周：CORE-05–08 + 一个场景模块。
- 第 9–12 周：CORE-09–10，完成端到端作品并复测。

目标：从 L0/L1 进入稳定 L2，而不是 90 天内追求多 Agent。

### 9.2 已经常用聊天 AI 的知识工作者

- 第 1–2 周：直接挑战 L2 项目，定位核验和任务表达缺口。
- 第 3–5 周：CORE-08–11。
- 第 6–9 周：CORE-12–15 + 场景专长 02。
- 第 10–12 周：完成协作项目档案并复测。

目标：从“高频使用”转为可解释、可复用、可核验的 L3 协作。

### 9.3 会编程但没做过可靠 Agent 的开发者

- 第 1–2 周：挑战 M/V 诊断；补 CORE-08、09、14。
- 第 3–5 周：SYS-01–03。
- 第 6–8 周：SYS-04–06。
- 第 9–12 周：SYS-07 试运行和回归评测。

目标：避免“能调 API = 会构建可靠系统”的假高阶。

## 十、地图的验证指标

学习地图是否有效，不能只看视频完播率，主要看：

- 模块前后同能力平行任务的表现变化；
- 作品验收通过率和第二次迁移成功率；
- 核验、隐私和高风险判断错误率；
- 模板/SOP 被他人复用的成功率；
- 30/90 天仍能独立完成任务的比例；
- 推荐课程的开始率、完成率和短板改善率；
- L4/L5 项目的稳定性、事故率、采用率与价值指标。

## 附录：模块与等级的最小必修集合

| 目标等级 | 最小通用集合 | 可替代条件 |
|---|---|---|
| L1 | CORE-01–03 | 直接通过概念、安全和第一次任务挑战 |
| L2 | CORE-04–09 + 1 个场景 01 | 提交等价真实作品并通过核验 |
| L3 | CORE-10–15 + 场景 02 | 提交复杂协作档案并通过答辩 |
| L4 | SYS-01–07 + 场景 03 | 提交真实运行系统及评测/安全证据 |
| L5 | ORG-01–05 | 提交真实组织采用与治理证据 |

“通过挑战可跳课”不等于降低标准；它是用更强的表现证据替代学习过程证据。
