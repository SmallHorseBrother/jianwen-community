# 个人 AI 能力框架 v1.0

> 英文名：Personal AI Capability Framework（PACF）  
> 版本：1.0.0  
> 日期：2026-08-09  
> 适用对象：成人学习者、知识工作者、内容创作者、创业者、研究者与非技术/技术从业者  
> 配套文档：[研究底稿](./00-research-basis.md) · [学习地图](./02-ai-learning-map-v1.md) · [能力—课程矩阵](./03-competency-curriculum-matrix-v1.md)

## 一、框架要解决什么

PACF 回答三个问题：

1. **我现在能用 AI 稳定完成什么？**
2. **我的短板是知识、任务表达、工具、核验、创造，还是系统能力？**
3. **下一步应学什么，并用什么作品证明已经学会？**

它不是工具熟悉度排行榜，也不是人格测试。人格画像回答“我偏好怎样使用 AI”；能力框架回答“我能否在给定风险和质量要求下完成任务”。两者可以合并呈现，但必须分开计分。

## 二、设计原则

### 2.1 测表现，不测气势

- “每天用”“很有信心”“收藏了很多提示词”不直接计分。
- 能力证据优先级：真实作品/实作 > 情境决策 > 客观知识 > 自我报告。
- 使用风格、自信度和学习意愿可用于解释，不得抬高能力等级。[S08][S10][S11]

### 2.2 技术中立，场景相关

- 等级名称不绑定 ChatGPT、Claude、豆包、DeepSeek、Coze 等具体产品。
- 示例工具可以更新，稳定能力 ID 不随产品改名。
- 同一能力必须能迁移到陌生工具或新任务。

### 2.3 责任随能力升级

- 初级学习“不泄露、不盲信”；高级学习权限、监控、治理和失效处置。
- 在高风险任务中，选择不使用 AI、降低自动化或升级人工复核，属于高水平表现。
- 输出责任不会因“AI 生成”而转移给模型。[S05][S06][S20–S22]

### 2.4 编程是专长，不是全民门槛

- C03“原型与实现”允许代码、低代码、无代码三条证据路径。
- 非程序员可以达到 L4，只要能设计、验证和运营可靠系统，并能与技术角色协作。
- 开发者也不会因为会写代码自动获得高等级；核验、治理和任务价值仍需单独证明。

### 2.5 从最小可靠方案开始

能力升级顺序是：

`单次辅助 → 可复用协作 → 固定工作流 → 有条件的 Agent → 组织系统`

不是：

`聊天机器人 → 多 Agent 越多越高级`

Workflow 遵循预定义路径；Agent 让模型动态选择步骤和工具。两者都只是实现方式。[S17–S20]

## 三、核心术语地图

| 概念 | 本框架中的定义 | 常见误区 |
|---|---|---|
| AI | 能执行感知、预测、生成、决策支持等任务的一类系统 | AI 就等于聊天机器人 |
| 模型（Model） | 从输入产生预测或生成结果的核心计算组件 | ChatGPT/豆包本身就是某一个模型 |
| 大语言模型（LLM） | 基于语言模式处理和生成内容的模型；输出具有概率性 | 像数据库一样“知道并检索”所有事实 |
| 产品/应用 | 将模型、界面、账户、数据、工具和安全策略封装给用户的服务 | 换应用就是换了一种能力 |
| 提示/指令 | 给模型的目标、上下文、约束、材料、样例和输出要求 | 存在万能咒语，可保证正确 |
| 工具调用 | 模型或程序调用搜索、代码、数据库、日历等外部能力 | 只要能调用工具就是 Agent |
| 检索/RAG | 在生成前后检索指定知识，并把相关内容作为依据 | 接了知识库就不会幻觉 |
| 自动化 | 按规则自动执行一组动作 | 自动化一定包含 AI |
| 工作流（Workflow） | 由人或代码预先定义路径、状态和分支的流程 | 工作流与 Agent 只是不同叫法 |
| Agent | 围绕目标在一定权限内循环计划、行动、观察和调整的系统 | Agent 是人格化聊天机器人；越自主越好 |
| 多 Agent | 多个具备不同角色/权限的 Agent 协作 | 多开几个对话窗口就是多 Agent |
| 上下文 | 当前推理可用的指令、历史、文件、检索结果和状态 | AI 永久记得所有聊天内容 |
| 幻觉/不实生成 | 输出流畅但包含错误、虚构或无法验证的内容 | 加一句“不要编造”就能彻底消除 |
| 评测（Eval） | 用数据集、标准和过程检查系统质量、风险与退化 | 看几个成功案例就算评测完成 |

## 四、总体架构：六维、六级、三类横切要求

### 4.1 六个能力维度

| 维度 | 代码 | 核心问题 | 权重 |
|---|---|---|---:|
| AI 心智模型 | M | 我是否理解正在使用的系统、边界和人机责任？ | 1/6 |
| 任务定义与沟通 | F | 我能否把模糊需求转成 AI 可协作、可验收的任务？ | 1/6 |
| 工具与信息素养 | T | 我能否选择并操作合适工具、数据和信息来源？ | 1/6 |
| 核验、安全与责任 | V | 我能否判断输出、控制风险并保留人工责任？ | 1/6 |
| 创造与执行 | C | 我能否把 AI 输出转成真实、可用、可复用的成果？ | 1/6 |
| 工作流与系统思维 | S | 我能否把单次成功变成可靠流程、系统和组织能力？ | 1/6 |

六维同权是 v1.0 的通用基线。岗位画像可改变推荐重点，但不能悄悄改变通用等级含义。

### 4.2 六个等级

| 等级 | 名称 | 一句话标准 | 典型证据 |
|---|---|---|---|
| L0 | AI 观察者（Orientation） | 知道 AI 存在，但尚不能安全、独立地使用 | 能识别基本概念与明显风险 |
| L1 | AI 辅助使用者（Assisted User） | 在模板或指导下完成低风险单步任务 | 完成一次受指导任务并做基础检查 |
| L2 | AI 独立操作者（Independent Operator） | 能独立完成常见真实任务并交付可用结果 | 陌生但同类的端到端任务作品 |
| L3 | AI 协作者（AI Collaborator） | 能分工、迭代、核验并管理复杂任务 | 多轮项目、证据链、过程记录和复盘 |
| L4 | AI 系统构建者（System Builder） | 能设计和运营可靠工作流/Agent | 流程图、实现、评测、监控与失败恢复 |
| L5 | AI 变革推动者（Transformation Leader） | 能将 AI 能力嵌入团队/组织并持续治理价值与风险 | 组织级方案、采用数据、治理机制和成效证据 |

### 4.3 三类横切要求

1. **人类主体性**：人定义目标、价值和责任；知道哪些判断不可外包。
2. **证据意识**：主张可追溯，质量可解释，不因表达流畅而降低审查。
3. **风险匹配**：任务风险越高，权限越小、核验越强、人工介入越早。

## 五、30 个能力单元

### 5.1 M：AI 心智模型

| ID | 能力 | 可观察定义 | 典型反证 |
|---|---|---|---|
| M01 | 系统构件辨析 | 区分模型、产品、提示、工具、检索、工作流、Agent 和多 Agent，并说明它们如何组合 | 把所有带 AI 的应用都称为模型或 Agent |
| M02 | 生成机制与不确定性 | 理解概率生成、输出波动、幻觉和能力边界，能据此调整使用方式 | 认为温度低/提示更强就一定正确 |
| M03 | 上下文、记忆与知识边界 | 理解上下文窗口、会话状态、长期记忆、文件和检索知识的差别 | 认为模型记得所有历史或自动知道最新事实 |
| M04 | 能力、成本与选择权衡 | 比较不同模型/产品在质量、速度、成本、隐私、工具和可用性上的取舍 | 只按排行榜或网红推荐选工具 |
| M05 | 人机分工与责任 | 决定哪些工作委派、保留或升级人工；明确最终责任人 | 用“AI 说的”替代判断或责任 |

#### M 维度等级锚点

| 等级 | 行为锚点 |
|---|---|
| L0 | 将 AI 视为会回答问题的黑箱，概念混用，容易拟人化或神化。 |
| L1 | 能区分模型与应用，知道输出可能错误、知识可能过时。 |
| L2 | 能解释上下文、检索和工具的基本作用，并为常见任务选择合适方式。 |
| L3 | 能根据任务结构、风险和成本设计人机分工，解释失败的系统性原因。 |
| L4 | 能比较单次调用、固定工作流和 Agent 架构，选择最小可靠方案。 |
| L5 | 能建立组织共同语言、技术选择原则和责任边界，并随技术变化更新。 |

### 5.2 F：任务定义与沟通

| ID | 能力 | 可观察定义 | 典型反证 |
|---|---|---|---|
| F01 | 问题与结果定义 | 把“帮我做一下”转成目标用户、业务目的和期望成果 | 只描述动作，不说明解决什么问题 |
| F02 | 任务拆解与委派 | 判断任务是否适合 AI，拆成可执行步骤并分配人/AI角色 | 将整项复杂任务一次性丢给模型 |
| F03 | 上下文与约束表达 | 提供必要材料、背景、边界、反例和禁止项，避免无关信息 | 迷信角色提示，缺少真实材料和限制 |
| F04 | 迭代、追问与状态管理 | 诊断偏差、精确纠偏、总结状态并在需要时重启/交接 | 在失控长对话里不断追加零散要求 |
| F05 | 验收标准与交付定义 | 在生成前定义准确性、完整性、格式、受众和通过条件 | 先看结果，再凭“感觉不错”验收 |

#### F 维度等级锚点

| 等级 | 行为锚点 |
|---|---|
| L0 | 使用模糊问句，把输出好坏主要归因于模型聪明程度。 |
| L1 | 能套用目标—背景—要求—格式模板完成简单请求。 |
| L2 | 能为常见真实任务补材料、拆步骤、设标准并独立迭代。 |
| L3 | 能管理多轮复杂协作、冲突约束、状态与人工交接。 |
| L4 | 能把任务契约、输入输出和停止条件固化进工作流或 Agent。 |
| L5 | 能建立跨团队任务规范、复用模板与质量协议，降低沟通成本。 |

### 5.3 T：工具与信息素养

| ID | 能力 | 可观察定义 | 典型反证 |
|---|---|---|---|
| T01 | 数字操作与账户基础 | 管理文件、格式、路径、账户、权限、上传下载和基本故障排查 | 被 API Key、压缩包、CSV、文件路径等基础概念完全阻断 |
| T02 | 工具与模型选型 | 按任务、风险、成本和集成条件选择工具，而非追新 | 为每个任务都换最新工具；或一个聊天框包打天下 |
| T03 | 搜索、检索与来源 | 区分生成与检索，设计查询，定位原始/权威来源并保存出处 | 引用 AI 生成但未打开的链接 |
| T04 | 多模态、数据与工作区 | 组织文本、图片、音频、表格、代码和文件，使其可被可靠处理 | 将材料无结构地全部上传，忽略格式/质量限制 |
| T05 | 集成、权限与资源成本 | 理解 API、Token、密钥、连接器、权限和基本成本；能安全配置或正确求助 | 把密钥写入公开页面；不给工具设权限边界 |

#### T 维度等级锚点

| 等级 | 行为锚点 |
|---|---|
| L0 | 账户、文件和数字安全基础不足，难以独立完成操作。 |
| L1 | 能使用一个主流聊天产品处理文本/图片并保存结果。 |
| L2 | 能在多个工具间选择，使用搜索、文件和基础多模态完成任务。 |
| L3 | 能组织来源、数据和工作区，使用高级检索或连接器实现稳定协作。 |
| L4 | 能配置 API/工具/权限/成本，设计安全的数据与工具链。 |
| L5 | 能制定组织选型、访问、采购、数据和技术债管理规则。 |

### 5.4 V：核验、安全与责任

| ID | 能力 | 可观察定义 | 典型反证 |
|---|---|---|---|
| V01 | 事实与来源核验 | 把关键主张对应到可打开的原始/权威来源，交叉验证时效与一致性 | 将模型自带引用视为已经核验 |
| V02 | 逻辑、质量与偏差审查 | 检查论证、计算、遗漏、适用性、偏差和受众影响 | 只改语气与排版，不检查内容 |
| V03 | 隐私、保密与知识产权 | 在上传/生成/分享前做数据分类、授权和版权判断 | 将论文未公开数据、客户资料或密钥输入不明服务 |
| V04 | 风险分级与人工监督 | 按影响和可逆性设置复核、审批、停止和升级人工条件 | 高风险决策全自动；出错后无人负责 |
| V05 | 溯源、披露与安全对抗 | 保留输入/版本/来源/操作记录，适当披露 AI 使用，并识别提示注入等攻击 | Agent 读取不可信内容后可直接执行高权限动作 |

#### V 维度等级锚点

| 等级 | 行为锚点 |
|---|---|
| L0 | 易把流畅度当正确性，对隐私和来源缺少基本警觉。 |
| L1 | 知道 AI 会错，能检查明显错误，不上传明显敏感信息。 |
| L2 | 能按清单核验关键事实、数据、引用、版权和适用性。 |
| L3 | 能根据风险设计证据链、独立复核、披露和人工审批。 |
| L4 | 能为系统设计权限最小化、评测、监控、攻击防护和恢复。 |
| L5 | 能建立组织治理、审计、事件响应和持续改进机制。 |

### 5.5 C：创造与执行

| ID | 能力 | 可观察定义 | 典型反证 |
|---|---|---|---|
| C01 | 内容与表达产出 | 利用 AI 完成面向真实受众的文本、视觉、音频、演示等成果，并保持个人判断 | 直接发布第一版通用文案 |
| C02 | 领域任务交付 | 将领域知识与 AI 协作结合，完成研究、办公、运营、学习等真实交付 | 脱离领域事实与工作标准，只展示 AI 效果 |
| C03 | 原型与实现 | 通过代码、低代码或无代码将想法做成可用原型，并能测试关键路径 | 只生成截图/代码片段，无法运行或验证 |
| C04 | 模板、知识与复用资产 | 把成功经验沉淀为模板、样例、知识库、组件或操作规范 | 每次从空白聊天开始，无法复现 |
| C05 | 效果测量与迭代 | 比较 AI 前后质量、时间、成本和风险，用反馈改进成果 | 以“感觉快了”作为唯一效果证据 |

#### C 维度等级锚点

| 等级 | 行为锚点 |
|---|---|
| L0 | 主要围观或娱乐性体验，尚无可用交付。 |
| L1 | 在模板帮助下生成一个低风险、可人工修订的成果。 |
| L2 | 独立完成常见领域任务，结果满足明确验收标准。 |
| L3 | 完成复杂项目，整合多种材料/模态并沉淀复用资产。 |
| L4 | 构建可被他人稳定使用的产品、流程或内部能力。 |
| L5 | 形成规模化产品/业务能力，并能证明持续价值与影响。 |

### 5.6 S：工作流与系统思维

| ID | 能力 | 可观察定义 | 典型反证 |
|---|---|---|---|
| S01 | 流程发现与价值定位 | 观察现有工作，找到高频、耗时、可标准化且值得改善的环节 | 因为“能自动化”就自动化低价值动作 |
| S02 | 工作流、状态与交接设计 | 定义步骤、分支、输入输出、状态、异常、重试和人机交接 | 只有 happy path，没有失败处理 |
| S03 | Agent 与工具编排 | 在确有需要时设计模型、工具、记忆和权限的动态循环 | 一上来多 Agent，缺少目标和边界 |
| S04 | 评测、可观测性与可靠性 | 建测试集、基线、日志、质量阈值、成本/延迟指标和回归机制 | 只演示一次成功，不知道长期是否退化 |
| S05 | 采用、治理与变革 | 设计角色、培训、政策、激励、支持和价值衡量，推动真实采用 | 部署工具后默认组织会自行改变 |

#### S 维度等级锚点

| 等级 | 行为锚点 |
|---|---|
| L0 | 把 AI 使用理解为一次次聊天，不观察完整流程。 |
| L1 | 能按简单清单重复一个固定任务。 |
| L2 | 能把个人任务整理成可复用 SOP，并明确人工检查点。 |
| L3 | 能跨工具管理状态、异常和交接，持续运行个人/小团队工作流。 |
| L4 | 能构建并运营含评测、监控、权限和恢复的 Workflow/Agent。 |
| L5 | 能重设计跨团队流程、治理组合系统并验证组织级改变。 |

## 六、等级判定规则

### 6.1 分数只是摘要，不是等级本身

每个维度标准化为 0–100，总分为六维平均。v1.0 暂定分数区间：

| 等级 | 暂定区间 |
|---|---:|
| L0 | 0–24 |
| L1 | 25–39 |
| L2 | 40–54 |
| L3 | 55–69 |
| L4 | 70–84 |
| L5 | 85–100 |

这些是上线前的**暂定切分**，不是自然定律。应在预测试后用项目难度、区分度、评委一致性和实际作品表现校准。

### 6.2 晋级门槛（Gates）

总分达到区间但未满足门槛时，报告为“总分接近 Ln，当前认证等级 L(n-1)”并说明原因。

| 目标等级 | 必须满足 |
|---|---|
| L1 | 完成基础安全题；能识别生成与搜索的差别 |
| L2 | 六维无一低于 L1；完成一个独立端到端任务 |
| L3 | V 维度至少 L2；完成复杂情境题和可核验项目 |
| L4 | V、S 至少 L3；实作通过；展示评测、权限和失败恢复 |
| L5 | V、S 至少 L4；通过组织级情境/案例答辩；有真实采用与价值证据 |

### 6.3 尖峰与短板

- 允许某人总等级 L2、C 维度 L4，这代表“强创造、系统/核验仍需补齐”。
- 报告不得把最低维度简单当成缺陷；先判断它是否构成当前目标的风险。
- 推荐顺序：**安全门槛 → 阻塞性前置能力 → 目标场景能力 → 兴趣拓展**。

## 七、测评证据模型

### 7.1 四类证据

| 类型 | 适合测什么 | 不适合单独证明什么 |
|---|---|---|
| 客观题 | 概念、边界、风险识别 | 稳定操作和真实交付 |
| 情境判断 | 选型、权衡、责任、异常处理 | 工具操作熟练度 |
| 开放作答 | 任务表达、拆解、标准、复盘 | 最终作品真实质量 |
| 实作/作品 | 综合执行、核验、迁移与交付 | 若只有一次样例，难证明长期稳定性 |

### 7.2 维度内权重

正式全测建议：

- 客观题：30%
- 情境题：30%
- 开放题与实作：40%

短测可以减少实作，但必须明确标注“筛查结果”，不能冒充专业诊断。

### 7.3 实作统一评分量规

每项 0–4 分：

| 指标 | 0 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|---|
| 目标与任务契约 | 无目标 | 模糊目标 | 有目标缺标准 | 目标、边界、标准较完整 | 能解释权衡并处理冲突 |
| 过程与人机分工 | 全盘丢给 AI | 步骤随意 | 有基本步骤 | 分工清晰、有检查点 | 根据反馈动态调整且可复用 |
| 结果质量 | 不可用 | 大量错误 | 基本可用 | 满足场景标准 | 对比基线有显著价值 |
| 核验与责任 | 无核验 | 口头声称核验 | 检查部分事实 | 证据链和风险控制完整 | 核验强度与风险匹配，可审计 |
| 复用与反思 | 无记录 | 只保留结果 | 有过程记录 | 沉淀模板/资产 | 有指标、复盘和下一轮改进 |

### 7.4 LLM 在评分中的边界

LLM 可以：

- 根据已验证 rubric 给开放作答生成**候选评分与理由**；
- 检查报告结构、提取作品证据、生成个性化解释；
- 从课程库检索推荐模块。

LLM 不可以：

- 自行发明题目分值、等级切点或晋级门槛；
- 用语言风格、篇幅、职业或自信度替代能力证据；
- 在未与人工金标准验证一致性前独立决定高风险等级；
- 看见姓名、性别、地域等无关特征后改变评分。

所有计分规则必须版本化、可复算。开放题上线前至少建立双人评分金标准，并报告一致性。

## 八、两种测评产品，共用一个题库

### 8.1 AI 能力快速筛查（Quick Check）

- 目标：识别大致起点和最优先短板。
- 时长：15–18 分钟。
- 建议：30 个计分交互，六维各 5 个；以客观题和短情境为主。
- 输出：暂定等级区间、六维概览、一个风险提醒、三步学习建议。
- 限制：不得输出“专业认证”或精细到个位数的能力结论。

### 8.2 AI 能力专业诊断（Full Diagnostic）

- 目标：课程分班、社群分流、成长基线与学习处方。
- 时长：45–55 分钟。
- 建议：40–45 个计分交互，含客观题、情境题、开放作答和 2 个实作。
- 输出：认证等级、六维分数、30 能力单元的强弱证据、门槛状态、学习路线和复测计划。

### 8.3 高阶应用实验室（Applied Lab）

- 目标：L4/L5 的真实系统和组织能力认证。
- 形式：带真实约束的项目、评测包、运行记录和答辩。
- 时间：数天至数周，不属于普通网页问卷。

### 8.4 题库规模与版本

- v1.0 建议先写 100–120 个候选交互，再选约 40–45 个进入全测。
- 每题至少标注：`item_id`、能力 ID、目标等级、题型、场景、风险、答案/量规、来源、版本、曝光状态。
- 快测与全测从同一题库抽取，避免两套分数含义分裂。

## 九、报告、课程和社群的连接

### 9.1 报告结构

1. 当前认证等级与一句话解释。
2. 六维雷达图（不建议默认展示 30 维）。
3. 三项优势证据、两项阻塞短板、一项风险提醒。
4. “你已经能做什么 / 暂时不要全自动做什么”。
5. 未来 30 天三步学习路线。
6. 推荐课程、练习作品和复测时间。

### 9.2 社群分流

| 群组 | 等级 | 主要任务 | 禁止形成的氛围 |
|---|---|---|---|
| AI 起步群 | L0–L1 | 概念纠偏、安全起步、第一次真实交付 | 晒工具压迫、术语优越感 |
| AI 应用群 | L2 | 场景练习、作品反馈、模板复用 | 只分享提示词不分享结果 |
| AI 协作群 | L3 | 复杂项目、核验、工作流共创 | 把 Demo 当稳定系统 |
| AI 系统群 | L4–L5 | Agent、评测、治理、组织案例 | 多 Agent 崇拜、忽略成本风险 |

四位入群 ID 和二维码只证明已解锁对应服务，**不参与能力计分**。复测后可更新推荐群组，但历史购买权益由商业规则单独管理。

### 9.3 复测

- 完成一个等级学习路径后，建议 30–90 天复测。
- 复测优先使用同能力的平行题，避免记答案。
- 报告比较行为与作品证据，不只比较总分。

## 十、公平性、可访问性与质量控制

1. **语言负担**：非语言维度避免用复杂文风充当能力门槛。
2. **数字基础**：T01 低分应触发补给课程，不应被解释为“没有 AI 潜力”。
3. **职业差异**：题目使用多个场景；不熟悉某行业不应误伤通用能力。
4. **技术可访问性**：提供移动端、清晰字体、进度保存和必要的无障碍说明。
5. **泄题控制**：建立平行题、曝光率和轮换机制。
6. **统计验证**：检查难度、区分度、内部结构、评分一致性、群体差异和预测效度。
7. **人工申诉**：高阶认证应允许提交补充证据或人工复核。

## 十一、版本治理

| 变化 | 是否升版本 | 例子 |
|---|---|---|
| 修正文案、不改含义 | Patch | 1.0.0 → 1.0.1 |
| 新增题目/课程，能力定义不变 | Minor | 1.0 → 1.1 |
| 维度、等级或计分含义改变 | Major | 1.x → 2.0 |

每个结果必须保存：框架版本、题库版本、评分版本、课程库版本、生成报告所用模型和时间。旧结果应能按旧规则复算，不能被新规则静默覆盖。

## 十二、v1.0 验收标准

框架进入公开测评前，至少满足：

- 30 个能力单元均有定义、反证、等级锚点和至少 3 个候选题；
- 六维各有一种非选择题证据；
- L2、L3 各有可复现实作；L4/L5 有独立应用实验室方案；
- 开放题评分与人工金标准完成首轮一致性测试；
- 由真正小白、普通知识工作者、内容/产品人员、开发者分别试测；
- 能解释“为什么这个人是该等级”，而不只给一个分数；
- 能把每个关键短板映射到具体课程和练习作品。
