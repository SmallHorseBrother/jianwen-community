## 一、矩阵的作用

这份矩阵把四件事锁在同一行：

`能力定义 → 前置能力 → 教学模块 → 结业证据`

因此它既是课程产品经理的范围表，也是题库、推荐引擎和内容生产的接口。任何新课程如果不能指出它提升哪个能力 ID、通过什么证据验证，就不进入核心课程体系。

## 二、现有资产判断

当前仓库已有：

- 六维、L0–L5 和约 30 道能力题的早期原型；
- 办公、内容、学习、产品、编程五个学习目标入口；
- 科研、创业、内容、Codex/自动化等真实案例素材；
- 若干已经运行的反馈、微信、任务和 Edge Function 工作流，可作为高阶案例。

但这些**不等于已经有完整课程**。现有题目大量依赖自我报告，也未按 30 个能力单元、行为等级和实作证据校准。所以下表把状态分成：

- `可复用原型`：现有题目/文案可作候选素材，需重写验证；
- `可复用案例`：本地项目能提供真实案例或演示，但仍需教学设计；
- `需要新建`：尚无系统课程资产；
- `高优先级`：若不先建设，会让能力链或安全门槛断裂。

## 四、矩阵覆盖规则

### 4.1 每个能力至少需要三类资产

1. **教**：概念说明、失败案例、示范和练习。
2. **练**：相似任务与陌生迁移任务。
3. **证**：可评分的客观/情境/开放/实作证据。

只有视频没有练习，或只有自评题没有作品，均视为未覆盖。

### 4.2 每个核心模块的验收

| 项目 | 最低要求 |
|---|---|
| 能力映射 | 1 个主要能力，最多 3 个次要能力；避免“一节课提升全部六维” |
| 前置能力 | 明确可跳过挑战和补给模块 |
| 学习目标 | 使用可观察动词：区分、选择、构建、核验、解释、修复 |
| 练习 | 至少一个真实错误案例和一个陌生迁移任务 |
| 证据 | 有评分标准，不以完成观看计分 |
| 更新层 | 稳定概念与易变工具操作分离 |
| 风险 | 标注数据、版权、错误行动和自动化风险 |

### 4.3 课程与测评不得循环论证

- 题目不能直接复制课程示例并用记忆答对。
- 结业任务与正式复测应使用平行场景。
- 推荐引擎根据缺失能力找课程；课程完成记录本身不能自动提高测评分数。

## 五、首批内容建设优先级

### P0：先补断点（第一批）

1. CORE-01：概念地图，解决模型/产品/Workflow/Agent 混淆。
2. CORE-02 + CORE-09：幻觉、隐私、责任和中国使用语境。
3. CORE-03 + CORE-08：任务契约、验收标准和质量核验。
4. CORE-04：搜索、检索、原始来源和假引用。
5. BRG-00/01：真正小白的数字操作与密钥安全。

### P1：形成 L2 商业核心

1. CORE-05–07：第一次真实交付、拆解迭代、工具/多模态。
2. OFF-01、RES-01、CON-01、PROD-01、DEV-01：五条入门场景。
3. CORE-10：把成果变成可复用 SOP。

### P2：形成 L3 差异化

1. CORE-11–15：复杂协作、证据链、知识资产、效果和团队审批。
2. 五条专长 02 项目。
3. 可公开展示的项目档案模板和同伴互评机制。

### P3：形成 L4/L5 高阶壁垒

1. SYS-01–07：可靠工作流与 Agent 工程。
2. ORG-01–05：组织用例、治理、采用和审计。
3. 将本地真实自动化项目改写为“成功 + 失败 + 评测”案例，而不只做功能演示。

## 六、与当前测评原型的迁移关系

当前 `catalog.ts` 的六维可以平滑迁移：

| 当前维度 | PACF v1.0 | 处理 |
|---|---|---|
| cognition | M 心智模型 | 保留方向，重写为客观概念/情境为主 |
| usage | T 工具与信息 | 拆出数字基础、来源和权限，不再以频率计分 |
| communication | F 任务定义与沟通 | 加入任务契约、状态和验收标准 |
| verification | V 核验、安全与责任 | 扩展到版权、监督、溯源、提示注入 |
| creation | C 创造与执行 | 用真实交付和复用证据替代“是否做过” |
| systems | S 工作流与系统思维 | 明确 Workflow/Agent/评测/治理的晋级链 |

当前 Level 命名与新框架含义并不完全相同，尤其原 L2“协作者”和原 L3“生产者”。迁移时必须保存旧版结果，不能直接改标签让历史分数看起来等价。

## 七、下一项资产：题库蓝图

矩阵确认后，题库按以下方式展开：

- 30 个能力 × 3–4 个候选交互 = 90–120 个候选；
- 每个能力至少 1 个边界/知识题、1 个情境题；
- F、V、C、S 的关键能力增加开放或实作；
- 快测抽 30 个筛查交互（六维各 5）；全测抽 40–45 个计分交互；
- L4/L5 另设应用实验室，不塞进普通网页选择题。

题库编写前应先冻结本矩阵的 P0 能力定义和模块边界，否则题目、课程和报告会继续互相漂移。
